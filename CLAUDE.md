# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static HTML/CSS/JS website for the Sunshine Coast Biomonitoring Portal (sunshinecoastbiomon.com) — no build system, framework, package manager, or test suite. Every page is a hand-authored `.html` file at the repo root, sharing a single `styles.css` and `nav.js`. There is nothing to install, build, lint, or test; editing is done directly against the served files.

## Previewing changes

Open the `.html` file directly in a browser, or serve the root over a simple local server (e.g. `python3 -m http.server`) since pages reference each other with relative paths.

## Site structure

- **Root-level `.html` files** are the actual pages. There is no `src/`, `dist/`, or templating layer — each page includes its own copy of the `<nav>` and `<footer>` markup (shared conventions, not shared includes), so structural nav/footer changes must be propagated to every page by hand.
- **`styles.css`** is the single stylesheet for the whole site, organized into labeled `/* ===== SECTION ===== */` blocks (nav, hero, page wrapper, headings, organization block, buttons, story cards, etc). Reuse existing classes/sections before adding new ones.
- **`nav.js`** only handles the mobile hamburger toggle.
- **`skills/scrd-biomonitor-writing-style/SKILL.md`** is the content style guide (voice, tone, formatting, citation format, and the fixed page templates below). Read it before writing or editing any page copy — it documents patterns that are otherwise only inferable by reading multiple existing pages.
- **`suggestion-*.html`** files are one-off design mockups/experiments, not live site pages.
- **`images/`** holds every image referenced by a page; **`archive/unused/`** holds assets (images, PDFs) not currently linked from any page, kept in case they're reused later.

## Content architecture (read the style guide for details)

Two page families follow strict, repeated templates rather than free-form structure — consistency across instances matters more than on other pages:

1. **Organization pages** (e.g. `sargeant-bay-society.html`) — a fixed sequence of a quoted mission blurb, then bolded fields in a fixed order (`Biomonitoring Programs:`, `Education Programs:`, `Biomonitoring and Community Science Volunteer Opportunities:`, `Website:`, `Location:`, `Contact:`), followed by two bottom buttons linking to `[org-slug]-data-repository.html` and `[org-slug]-methods.html`. Every org has all three files, generated by hand, following identical filename conventions.
2. **Biodiversity Research stories** (sections within `biodiversity-research.html`) — a fixed shape: category tag, hook opening, named/linked researcher, plain-language methods, explicit local tie-in, bolded "Key Finding/Takeaway" close, and academic citation(s). See the SKILL.md checklist before drafting a new one.

Every page shares the same `<nav>`/`<footer>` block and SEO metadata pattern in `<head>` (canonical URL, Open Graph tags, and a Google Analytics snippet on every page). New pages should copy this `<head>` and nav/footer structure from an existing page rather than reinventing it.

## Deployment

`robots.txt` and `sitemap.xml` point at `https://sunshinecoastbiomon.com/`; there's no CI/deploy config in this repo, so publishing happens outside of it.
